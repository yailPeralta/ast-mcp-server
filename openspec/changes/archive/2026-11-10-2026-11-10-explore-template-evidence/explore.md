# Exploration: template evidence in ast_explore (#380)

Change: 2026-11-10-explore-template-evidence. Phase: sdd-explore.

## Problem
ast_explore reference evidence comes from sync collectSymbolReferences (context-builder.ts:378), so a component member used only in its template looks unused. ast_find_references already merges template usages (collectSymbolReferencesWithTemplates, references.ts:202) with per-item origin, template_coverage, template_reference_count.

## Verified facts
- collectSymbolReferencesWithTemplates returns the sync result unchanged on not_applicable; otherwise merges TS locations (tagged origin "compiler") with template items, sorts by file:line:col, paginates ONE merged list (offset/limit), reference_count = TS refs only, template_reference_count = template items, total/has_more cover the merged list.
- collectTemplateUsages (angular-templates.ts:772) cost tiers: (a) no @angular/core resolved or non-Angular node -> NOT_APPLICABLE (cheap gate); (b) private component member -> reads/parses ONE template (<=512 KiB); (c) selector-public @Input/@Output member and @Pipe class/transform -> scanConsumers over every component in the Project, per-call SCAN_LIMITS 2000 templates / 32 MiB / 1M nodes, readTemplate (stat+readFile) for each component BEFORE the cheap mayMatch/includes skip, no cross-call read cache (only compilerCache for the compiler module). Failure modes return coverage (unfinished/unsupported + reason); only non-WorkExhausted errors throw.
- Coverage reason enum (find_references.ts:46-59): compiler_missing, compiler_unsupported, template_unresolved, template_unsafe, template_parse_error, size_exceeded, work_exhausted, inherited_member, cross_component.
- Explore: json-only direct (directOutputFormats ["json"]), output validated by ExploreOutputSchema.parse (strips unknown keys, so schema must be extended or fields vanish). Batch runs the same handler (ast-explore-batch-parity: parity of fields/omissions/completeness/bytes; TOON = representation only).
- Presentation: presentExploreClusters is generic (references: unknown). On byte_limit trimming it drops the whole evidence block and appends omission {component:"references", reason:"byte_limit"}; omissions passed in by builder are retained even when a cluster is trimmed/dropped. evidence_complete = no omissions && no unresolved.
- Errors from the references call today become unresolved {references_unresolved} (whole references block lost).
- Existing pin test/explore-unchanged.test.ts asserts the OPPOSITE of the feature (no template fields on Angular fixture; context-builder source must contain collectSymbolReferences( and not WithTemplates) -> must be inverted/replaced.
- ast_get_impact / ast_find_test_candidates do not import context-builder; isolation holds by construction.

## Decisions and recommendations
1. reference_limit: RECOMMEND shared limit through the existing merged pagination (identical to find_references). A separate template limit needs a new input property -> breaks frozen input schema (dsh-adapter); applying the limit independently to each origin would make "maximum" up to 2x and diverge from find_references. The frozen text "compiler references" becomes slightly inexact when template usages exist; cannot be edited (frozen), so document in skill/docs and spec ("reference_limit bounds the merged references list; origin tells TS vs template"). has_more still raises the existing reference_limit omission. Risk: dense TS refs can push template items off page -> visible via has_more/next_offset but explore passes offset 0 only; acceptable, point caller to ast_find_references for paging.
2. Coverage surfacing (all three, layered): (a) evidence[].references.template_coverage + template_reference_count + per-item origin, additive optional, only when not not_applicable; (b) NEW omission reason template_coverage_incomplete (category incomplete, component references, one per selector whose status != completed, added by the builder like references_unresolved so it survives byte_limit trimming); this also sets completeness.evidence_complete=false and complete=false for free via omissions.length; (c) when byte_limit drops the block, the existing byte_limit omission already says references absent, and the builder-level template_coverage_incomplete remains, so a non-completed verdict is never lost; reason detail (e.g. size_exceeded) is only in the untrimmed block (omission schema has no detail field; re-query ast_find_references). A completed verdict lost to trimming is harmless (byte_limit omission covers it). Add the new reason to EXPLORE_OMISSION_REASONS (output enum only). Do not drop unsupported/unfinished.
 Error policy: if the template-aware call throws a non-cooperative error, fall back to sync collectSymbolReferences and emit synthetic coverage {status unfinished, reason template_unresolved} + the omission, rather than losing TS evidence as references_unresolved (avoid regression vs today).
3. Scan budget/latency: RECOMMEND per-symbol budgets as today (verdicts stay deterministic and per-symbol honest; a shared budget would make verdicts order-dependent), no new restriction beyond the existing detail/include_references gate, and a MEASUREMENT task before adding a cache. Cost is only large for selector-public members and pipes; private members cost one template. Worst case 20 symbols x up-to-2000 template stat+read each, bounded cooperatively by requestContext timeout checkpoints. If measurement shows need: request-scoped template read cache (Map keyed by absolutePath, optional param on collectTemplateUsages/readTemplate) as a follow-up, not in the first slice (touches shared module used by rename). Measure: wall time and readFile count for detail=full limit=20 on fixtures of 50/500/2000 components with 20 @Input members vs same without Angular (baseline) and vs ast_find_references; cold vs warm compiler load; peak RSS; timeout behavior.
4. Symbol scope: RECOMMEND delegating to collectTemplateUsages unchanged: explore calls it for every record node and inherits whatever it supports (private/own-template members, selector-public inputs/outputs consumer scan, @Pipe class and transform, inherited_member unsupported verdicts). Restricting to "component members" would diverge from find_references verdicts, contradicting the requested "same coverage verdict". Spec states parity, not a member list.
5. TOON/batch: explore direct output is JSON only; batch TOON is representation-only, no explore-specific code. Merged items all carry origin in Angular case (compiler/template_*), so arrays stay uniform; add a batch-parity test with an Angular fixture (direct vs batch equal, TOON decode equal). Presentation changes limited to the enum value. Non-Angular output deep-equals today: keep a golden/deep-equal test on a non-Angular fixture and an Angular non-applicable node.
6. Schema fragment: RECOMMEND extracting the leaf schemas (origin enum, TemplateCoverageSchema with reasons, template_reference_count field) from find_references.ts into one small shared module (e.g. src/tools/template-evidence-schema.ts) imported by both tools; find_references JSON schema must stay byte-identical (guard: tool-inventory/tools_list hash for find_references unchanged). Avoids duplicating the 9-reason enum (drift risk). Explore adds origin to ExploreReferenceSchema and the two fields on the references object, all optional.

## Affected areas

## Risks
- Output schema change re-pins tools_list_sha256 in three places; forgetting canary/registry smoke fails release gates.
- Tool descriptions frozen: feature discoverable only via output + skill docs.
- Latency regression on large Angular workspaces with @Input-heavy detail=full (mitigation: measure; cache follow-up).
- Behavior change: throws inside template path previously impossible; mitigated by fallback.
- Shared limit lets template items displace TS refs and vice versa; documented.
- Inverting the explore-unchanged pin is a deliberate contract change; keep non-Angular deep-equal guard.
