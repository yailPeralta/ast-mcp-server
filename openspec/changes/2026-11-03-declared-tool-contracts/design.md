# Design: Declared tool contracts in the dsh-adapter smoke

Issue #383. Proposal: `proposal.md` (Option B). Two chained PRs: U1 (gate infrastructure, behavior identical to today), U2 (two declarations, three pins, docs).

## Technical Approach

The comparison logic leaves the 2200-line smoke and goes into a pure, importable ESM module, `scripts/lib/declared-tool-contracts.mjs`. The module owns three things: semantic normalization (`semanticSchema`, moved from the smoke), the declared-contract rules, and the evidence digests. It does not own Harness journeys, the `ast_explore` RED/corrected checks, process exit or I/O. The smoke reads the fixture, builds two maps keyed by bare tool name from the two journeys, calls `compareToolContracts` and asserts `ok`. The rules are unit-tested in vitest without the smoke. One real smoke run per PR is the integration proof.

## Interfaces / Contracts

```js
// scripts/lib/declared-tool-contracts.mjs (+ declared-tool-contracts.d.mts, following the agent-fixtures precedent)
export const RESERVED_TOOL_NAMES; // Object.freeze(["ast_explore"])
export function semanticSchema(node, root = node); // moved verbatim from the smoke
export function contractFromTool({ description, inputSchema }); // -> { description, input_schema: semanticSchema(inputSchema) }
export function compareToolContracts({ publicTools, candidateTools, declared, baselineVersion });
export function formatContractFailures(failures); // -> string
```

- `publicTools` and `candidateTools`: `Record<bareName, { description: string, parameters: object }>`.
- `declared` is the parsed fixture: `{ baseline: string, tools: Record<bareName, { description, input_schema }> }`. Each entry has exactly these two keys.
- Result: `{ ok, failures: [{ tool, field, reason }], tools: { [name]: { status: "undeclared" | "declared", publicSha256, candidateSha256, declaredSha256? } }, undeclaredSha256: { public: string | null, candidate: string | null } }` (null when the catalogs or the fixture are malformed and the comparison returns early with `tools: {}`).
- Allowed `field` values: `baseline | catalog | declaration | description | input_schema | additionalProperties`.
- Allowed `reason` values: `baseline_mismatch | names_differ | malformed | unknown_tool | reserved_tool | drift_from_public | stale_equals_public | mismatch_declaration | loosened`.
- `failures` is sorted by `tool`, then `field`. Use `"*"` for whole-catalog failures.
- Digests are `sha256(JSON.stringify({ name, description, parameters: semantic }))`, using `node:crypto`. They are deterministic and involve no clock or I/O.
- The function never throws on bad data and never calls `process.exit`.

Rules: an undeclared tool must equal public. A declared tool must equal its declaration and must differ from public (`stale_equals_public`, reported once per tool on the `description` field because the declaration as a whole is stale; the `declaration` field is reserved for `reserved_tool`, `unknown_tool` and `malformed`). A declaration fails when its tool is unknown or missing on either side, or when it names `ast_explore`. `declared.baseline` must equal `baselineVersion`. Strictness applies to every non-reserved candidate tool.

Failure message: `` `declared tool contracts failed: ${formatContractFailures(result.failures)}` ``. Each item is `tool.field: reason`, joined by `"; "`. Example: `ast_rename_symbol.description: stale_equals_public`.

## Data Flow

```
test/fixtures/declared-tool-contracts.json ──readFile+JSON.parse──┐
runNativeAgentJourney(public)    → toolContracts (bare-name map) ──┤
runNativeAgentJourney(candidate) → toolContracts (bare-name map) ──┼─▶ compareToolContracts(..., PUBLIC_BASELINE_VERSION)
                                                                   │      ok? else assert(false, message)
                                                                   └─▶ summary.h02.declaredContracts = { baseline, tools, undeclaredSha256 }
```

`runNativeAgentJourney` gains `toolContracts`, built from the `astTools` it already has. It is removed before `summary.h01a`, which keeps the printed summary size unchanged. The assertion at 2123-2129 drops only its `unaffectedSemanticSha256` clause, the strictness assertion at 2133-2138 is replaced by the module check, and `schemaEvidence` stays as it is.

## Re-baseline procedure (U2, in order)

1. On the U1 base, confirm the current pins are green: `yarn build && vitest run test/mcp.integration.test.ts test/supervised-worker.integration.test.ts`. Inspect the git history of `tools_list_sha256` before editing.
2. Add the fixture entries, then change the two descriptions until the oracle test is green.
3. **tool-inventory**: take the received hex from the failing `mcp.integration` assertion. **registry-consumer**: set the same value. It uses the same formula (SDK `Client.listTools()`); today both are `a7027585…`, and a new test asserts they stay equal.
4. **canary**: run `yarn build`, then `vitest run test/supervised-worker.integration.test.ts`, and read the digest printed by `assertExpectedToolInventory` (`…independent oracle (<hex>)`). Commit that value and rerun until green. Never copy it from step 3. The canary speaks JSON-RPC to its own spawned server through `CanaryMcpProcess` (`scripts/canary-local-mcp.mjs:3144`), validates only the envelope with `JSONRPCMessageSchema` (line 3089) and hashes `JSON.stringify(result.tools)` with the `tools` array left unparsed (line 205), under `childEnvironment` (`AST_MCP_APPLY_GUARD=allow`, line 2709). The other two pins hash SDK `Client.listTools().tools` (`test/mcp.integration.test.ts:531-534`, `scripts/registry-consumer-smoke.mjs:865-867`), whose zod result parsing can reorder or reshape keys. That client difference, not the guard (which only filters apply when deny; both lists have 16 names), is why `fa9a5661…` ≠ `a7027585…`. Independence is the rule.
5. Write the docs: turn CHANGELOG "Deferred tool description text" into a Changed entry, add the declared-contract rule to the README, and write the ADR 0015 addendum (lifecycle: declare, change source, re-baseline three pins, drop the declaration when the baseline advances; the stale rule enforces the drop).
6. Run `yarn test`, `yarn test:package`, `yarn test:dsh-adapter` and `yarn test:local-registry`.

## Threat Matrix

N/A. The change adds no routing, shell, subprocess, VCS/PR automation, executable-file classification or process-integration boundary. The smoke's existing subprocesses are untouched, and the module is pure.
